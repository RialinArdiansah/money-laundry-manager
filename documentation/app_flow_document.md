# App Flow Document for Money Laundry Manager

## Onboarding and Sign-In/Sign-Up
A new user accesses the app by navigating to the landing page or a direct link. The landing page displays options to sign in or create an account. When the user chooses to sign up, they enter an email address, a password, and any required personal details. The system sends a confirmation email to verify the address before the account is activated. Once confirmed, the user is redirected to the sign-in page. For returning users, the sign-in page accepts email and password and authenticates via Better Auth. A “Forgot Password” link is available on the sign-in form. When clicked, the user is prompted to enter their email address. The app sends a reset link to that address. Following the reset link allows the user to set a new password and return to the sign-in form. A signed-in user can log out at any time by using the sign-out button in the header, which returns them to the landing page.

## Main Dashboard or Home Page
After signing in, the user lands on the main dashboard. A collapsible sidebar on the left shows navigation items such as Dashboard, New Order, Customers, Transactions, Status Check, and, for owners, Employees. The header at the top displays the logged-in user’s name, a notification icon, and a profile menu with links to Settings and Sign Out. The central area presents summary widgets and tables. For an employee, the dashboard highlights recent orders and tasks that need attention. For an owner, it shows metrics like total revenue, number of active orders, and a chart of completed jobs. Every widget and table is interactive, allowing users to click through to detailed pages by selecting links or table rows.

## Detailed Feature Flows and Page Transitions
When an employee wants to register a new laundry order, they click the New Order link in the sidebar. This navigates to the Order Entry page, which features form fields for customer selection or creation, service type, weight, entry date, and estimated completion date. The user fills out each field and clicks the Save button at the bottom. The form submits a POST request to `/api/orders`. If successful, a confirmation toast appears and the user is redirected to the Transactions page. On the Transactions page, the app displays a paginated and filterable data table of all orders. The employee can click on any order to view its details on the Order Detail page, where they can also update the order status by selecting a new status in a dropdown. When the status is changed and the user confirms, a PUT request is sent to `/api/orders/[orderId]/status`, and the table is updated in real time. To view or modify customer records, the user clicks the Customers link. The Customers page shows a data table of customer profiles with search and filter controls. Clicking an existing customer opens a profile page where the user can edit details and save changes via `/api/customers/[customerId]`. Owners see an additional Employees link in the sidebar. On the Employees page, they can view all staff members in a table and add a new employee by clicking an Add Employee button. This opens a form similar to the Order Entry page, which submits data to `/api/employees`. All pages use consistent UI components so navigation feels seamless. The Status Check page is publicly accessible; users enter an order number in a lookup form, the app sends a GET request to `/api/orders/[orderId]`, and then displays the current status, entry date, and expected completion date in a card layout.

## Settings and Account Management
Users access account settings through the profile menu in the header. The Settings page presents personal information fields such as name, email, and contact number. Users can update their password in a dedicated section by entering the current password and the new password twice. The page also includes toggles for notification preferences, for example to receive email updates when statuses change. When the user saves changes, the app sends a PUT request to `/api/users/[userId]` and displays a success message. After saving, the user can return to the dashboard by clicking the Dashboard item in the sidebar or the app logo in the header.

## Error States and Alternate Paths
If a user enters invalid data anywhere in the app, such as a required field left blank on the Order Entry page or an incorrect login credential, the form displays an inline error message next to the relevant field or at the top of the form. Network errors trigger a full-page message informing the user that the connection was lost and offering a Retry button. Attempting to access a restricted page without the proper role, such as an employee opening the Employees page, shows an “Access Denied” screen with an explanation and a link back to the dashboard. The app also handles 404 errors: if a user visits a nonexistent route, they see a friendly page with a message that the page cannot be found and a button to return home.

## Conclusion and Overall App Journey
A user starts by signing up and confirming their email, then logs in to reach a customized dashboard based on their role. From the dashboard, they can record new laundry orders, manage customers, track and update order statuses, or, for owners, manage employees. At each step, the app uses consistent UI components and clear API calls behind the scenes. Users can update their account details in Settings or sign out when they are done. The typical end goal is to complete laundry orders on time and maintain accurate records of customers and staff, all through a smooth and connected journey from login to order completion.
